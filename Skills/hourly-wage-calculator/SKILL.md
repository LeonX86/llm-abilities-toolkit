# 时薪计算器

## 第一步：参数完整性检查

时薪计算需要以下四个参数**全部具备**，缺一则直接询问用户补全，不继续执行：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| 月薪 | 每月工资金额 | 无，必须提供 |
| 上班时间 | 每天上班时刻 | 上午9点（9） |
| 下班时间 | 每天下班时刻 | 下午6点（18） |
| 每周工作天数 | 每周上班天数 | 5天 |

### 快捷作息码解析

用户可能用数字串表示作息，格式为 `上班时` + `下班时(原始)` + `每周天数`，下班时间 ≤ 12 则视为下午，+12 转为24小时制：

| 输入 | 上班 | 下班（24h） | 每周天数 |
|------|------|-------------|----------|
| 955  | 9    | 17          | 5        |
| 996  | 9    | 21          | 6        |
| 965  | 9    | 18          | 5        |
| 966  | 9    | 18          | 6        |
| 10107| 10   | 22          | 7        |

---

## 第二步：参数提取

| 参数 | 类型 | 说明 |
|------|------|------|
| `salary` | 数字 | 月薪金额。`10k`→`10000`，`2w`→`20000` |
| `work_time` | 数字（24h制） | 上班时刻，"早上9点"→`9` |
| `off_time` | 数字（24h制） | 下班时刻，"下午6点"→`18`，作息码下班时间≤12则+12 |
| `week_days` | 数字 | 每周工作天数，未提及默认`5`。**若用户描述的是非标准作息（每周上班天数不固定，如大小周、两周休一天等），此处填写"基准最低保证天数"而非实际平均天数，具体规则见第三步。** |
| `month_in_prompt` | 字符串 | 有明确月份→`2026-05`；只有月份→拼当前年；未提及→`0` |

---

## 第三步：运行计算脚本

**传入脚本的 `week_days` 必须是"基准最低保证天数"，确保后续调整只有加法，没有减法。** 规则：

- 用户作息固定（955 / 965 / 996 / 10107 等）→ 直接使用对应天数，正常计算，无需额外调整
- 用户作息含周期性额外上班（大小周：`week_days=5`，大周多的那天在输出时加）
- 用户作息含周期性少上班（如 777 但两周休一天）→ 取**去掉休息规律后的最小固定天数**（此例取 `week_days=5`，把实际多上的周六、周日在输出时加）；**不要用 7**，否则后续调整变成减法

参数确定后执行：

```bash
python scripts/calc.py --salary {salary} --work-time {work_time} --off-time {off_time} --week-days {week_days} --month {month_in_prompt}
```

**示例：**

```bash
python scripts/calc.py --salary 15000 --work-time 9 --off-time 18 --week-days 5 --month 0
```

脚本输出 JSON，包含以下字段：

| 字段 | 含义 |
|------|------|
| `month_str` | 计算月份，如 `2026-05` |
| `total_days` | 当月总天数 |
| `work_days` | 当月工作日天数（含补班，排除节假日） |
| `rest_days` | 当月休息日天数 |
| `rest_day_list` | 休息日日期列表（含节假日、普通周末） |
| `makeup_day_list` | 补班日日期列表 |
| `calendar_md` | 当月日历 Markdown 表格，每天标注 `工作` / `休息` / `**补班**`；API 不可用时首行附带说明 |
| `daily_work_hours` | 每日工作时长（小时） |
| `monthly_work_hours` | 当月总工作时长（小时，基准作息） |
| `hourly_rate` | **时薪（元/小时）** |

> 脚本依赖 `requests`，需确认已安装。节假日数据来源于 [timor.tech](http://timor.tech/api/holiday)，API 不可用时自动回退到按星期计算。

---

## 第四步：以 Markdown 格式输出结果

根据脚本输出的 JSON，直接以 Markdown 输出以下三部分（**不要用代码块包裹**），**顺序固定为：日历 → 汇总表 → LaTeX 公式**。

根据用户的原始输入信息**判断是否存在非标准作息**（大小周、隔周休、两周一休等任何周期性但每周不固定的排班），通过阅读日历表识别额外工作天数后，再填写汇总表与公式。

### 1. 当月日历

**日历表**：输出 `calendar_md`。非标准作息时，先将日历中额外需要上班的日期对应的 `休息` 改为 `**额外**`，再输出修改后的表格。由此确认 `extra_work_days` 的具体数值，供后续汇总表与公式使用。

**休息日与补班**：使用代码块包裹，用紧凑单行列表格式，休息日参考`rest_day_list`完整输出（给用户参考基准的所有休息日），但非标准作息时在额外需要上班的日期后标注 `（额外）`：

```
休息日：['2026-05-16（额外）', '2026-05-23', '2026-05-30（额外）', '2026-05-10', ...]
补班日：['2026-04-27']   # 若为空则输出 []
```

### 2. 参数与结果汇总表

**若存在非标准作息，在表格前先输出一行说明（斜体）：**

> *根据您提供的{用户描述的作息}，以{week_days}天/周作为基准计算，实际因{作息规律}本月额外工作约 N 天（X 小时），以下表格已体现调整。*

表格行数固定，非标准作息时在对应单元格的数值中内联展示调整计算式：

| 项目 | 数值 |
|------|------|
| 月薪 | `{salary}` 元 |
| 上班时间 | 早上 `{work_time}` 点 |
| 下班时间 | `{off_time}` 点（24小时制） |
| 每周工作天数 | `{week_days}` 天 |
| 计算月份 | `{month_str}` |
| 当月总天数 | `{total_days}` 天 |
| 当月休息日 | 标准作息输出 `{rest_days}` 天；非标准作息输出 `{rest_days}-{extra_work_days}={actual_rest}` 天 |
| 当月工作日 | 标准作息输出 `{work_days}` 天；非标准作息输出 `{work_days}+{extra_work_days}={actual_work}` 天 |
| 每日工作时长 | `{daily_work_hours}` 小时 |
| 当月总工作时长 | 标准作息输出 `{monthly_work_hours}` 小时；非标准作息输出 `{monthly_work_hours}+({daily_work_hours}×{extra_work_days})={actual_hours}` 小时 |
| **时薪** | 标准作息输出 **`{hourly_rate}` 元/小时**；非标准作息输出 **时薪由 `{hourly_rate}` 降至 `{actual_hourly_rate}` 元/小时** |

以上四行每行二选一输出，不要在单元格内同时出现两种值，也不要出现"标准"/"非标准"字样。

### 3. 计算过程（LaTeX 公式）

用连等号代入实际数值展示推导过程。
**非标准作息时**，在公式前加一行斜体说明，并在第二行展开额外时长的乘法，最后一行展示实际时薪及差值：

$$\text{每日工作时长} = \text{下班} - \text{上班} = 18 - 9 = 9 \text{ 小时}$$

$$\text{当月总工作时长} = 9 \times 22 \underbrace{+ 9 \times 3}_{\text{非标准额外}} = 198 + 27 = 225 \text{ 小时}$$

$$\text{时薪} = \frac{15000}{225} \approx 66.67 \text{ 元/小时} \quad \left(\text{较标准制少赚 } 75.76 - 66.67 = 9.09 \text{ 元/小时}\right)$$

标准作息时第二行不含 `+` 展开项，第三行不含差值括号。**输出时将所有示例数值替换为用户的实际数值。**
